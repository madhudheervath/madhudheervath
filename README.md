## About

I'm a **Full Stack AI Engineer** at **Arivaan AI**, where I work on a live, credit-metered AI platform: seven products served from one Node.js / Express / PostgreSQL backend. I built five of them end to end: **Chat, Assistant, Studio, Trip Planner and Social Manager**.

My engineering focus is **correctness under real-world conditions**. That means billing that never double-charges under concurrent or failed requests, background jobs that never double-post across instances, and AI agents whose output is checked by executable evidence rather than trusted on confidence.

- **Software engineering:** transactional PostgreSQL, concurrency control, job queues, WebSockets, payments and webhooks, authentication and 2FA, 2,900+ automated tests on the platform
- **AI / ML:** LLM routing and fallbacks, RAG, tool-calling agents, real-time voice AI, model evaluation, diffusion models, audio ML
- **Full stack:** React, Next.js, Node.js, FastAPI. I take features from schema to UI to deployment.
- **Product mindset:** I design for the failure path first, measure what ships, and report results honestly, including negative ones.

**Open to:** Software Engineer · Full Stack Engineer · AI / ML Engineer roles · freelance product builds

## Featured Projects

<details open>
<summary><b>ProofPatch: Verification-First Agentic CI Repair</b></summary>

<br/>

An agent that repairs failing CI only when it can **prove** the fix. It reproduces the historical failure in Docker, lets an LLM investigate through bounded tools, seals the candidate patch, and certifies it in a fresh sandbox the agent never touched. If the evidence is weak, it abstains.

| | |
|:--|:--|
| **Stack** | Python · Docker · LLM tool calling · pytest |
| **Scale** | ~14k-line package; unit, integration and security test suites |
| **Performance** | Live end-to-end Docker repair in 140 s (reproduce → seal → certify → regression → policy) |
| **Security** | Isolated sandboxes, patch security guard, hash-verified certificates |
| **Impact** | Built for the **micro1 Frontier Engineering Challenge 2026** |
| **Repository** | [madhudheervath/ProofPatch-Verification-First-Agentic-CI-Repair](https://github.com/madhudheervath/ProofPatch-Verification-First-Agentic-CI-Repair) |

ProofPatch separates *proposing* from *proving*. The model may investigate and suggest a patch, but only executable evidence can produce `VERIFIED_REPAIR`. Everything else ends in an honest `ABSTAINED`.

</details>

| | |

| **Security** | — |
| **Impact** | Found and fixed 5 GPU issues running SDXL on 16 GB cards (fp16 VAE overflow, `device_map` conflict) |
| **Repository** | [madhudheervath/GenAI](https://github.com/madhudheervath/GenAI) |

Built on multi-branch denoising, a custom attention processor that keeps cross-attention maps differentiable, InfoNCE latent updates and masked latent fusion. The SDXL port uses a 24×24 attention grid at 768×768.

<summary><b>PlantWave: Plant Water-Stress Detection from Audio</b> · B.Tech Thesis</summary>

<br/>

A 14-day study testing whether plant audio signals can distinguish water-stressed plants from well-watered ones.

| | |
|:--|:--|
| **Stack** | Python · librosa · TensorFlow (YAMNet) · PyTorch (AST, Wav2Vec2, HuBERT) · LightGBM |
| **Scale** | 10 species, ~590 recordings, 4 modelling approaches |
| **Performance** | Held-out accuracy 46–54% across deep models vs 87–100% training accuracy |
| **Security** | — |
| **Impact** | Showed no reliable stress signal in the audio; recommended raw electrical-signal sensing |
| **Repository** | [madhudheervath/PlantWave-Audio-Analysis](https://github.com/madhudheervath/PlantWave-Audio-Analysis) |

A rigorous negative result. Per-species statistics found significant feature differences (e.g. Bamboo Palm, 7 of 22 features, d = 0.74), but no classifier generalised beyond chance.
